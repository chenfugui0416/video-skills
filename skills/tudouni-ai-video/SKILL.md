# 土豆泥 AI 口播视频

将定稿变成音频驱动的知识视频。先理解观众要学会什么，再安排角色、证据、图形和动画。用户当前指令、项目规则和已经授权的制作范围优先。

## 开始与范围

- 找到当前定稿、制作状态、最终音频、时间轴、视觉编排和资产清单。有效结果直接复用；改画面不重合成配音。编辑已有片子保留原版，另存版本。
- 只要求编排表时就交付编排表；只要求选动效时就交付模板骨架与最小修改方案。已授权继续制作时，按既有选择推进，不重复问批准过的文案、音色与配色。
- 缺必要输入时先完成独立工作，再集中问必要信息。没有真实配音时间轴，只能给无时间草案，不能填估计毫秒。
- 工程放在 iCloud 外的缓存目录；交付视频放进对应项目 `video/`。不修改账号配置或发布视频。

## 个人默认值

- 品牌名称：**土豆泥今天AI了吗**；栏目：**土豆泥讲 AI**。用于视频标识，不据此修改平台账号。
- 奶油底 `#F5F0E8`、纸面 `#FFFCF7`、品牌蓝 `#0F4C81`、蓝灰 `#4F6B8F`、正文 `#2E3A4F`、辅助文字 `#596779`；暖橙 `#FFB74D` 只作局部重点。
- 人物沿用 FUGui 原身份；柔和手绘配清楚的信息排版，精确中文交给排版工具。参考位置与角色候选状态见 [导演与风格](references/directing-style.md)。
- 已选音色：豆包 TTS 2.0 **活力小哥** `zh_male_huolixiaoge_uranus_bigtts`，语速 1.0，默认音量。用户要求时才更换，不能无声降级其他服务。
- 当前知识讲解片默认 **1920×1080、16:9 横屏、30fps**，时长由音频决定；右上角全程保留 **“土豆泥讲 AI”** 水印，留出安全边距。平台需要竖版或用户另有要求时再适配。54 秒、六镜或十镜都是案例，不是通用限制。

## 制作顺序

1. **冻结文案与事实**：只朗读定稿正文，记录哈希。产品界面、数据、能力与案例需真实来源；缺素材标“需要补充素材”。不同主题重新理解语义，不套旧镜头文案。
2. **配音接对齐**：整段文案只发起一次合成请求，禁止分句或分段多次请求再拼接。输出 44100Hz、单声道、16bit `audio/vo-full.wav`。接着用中文 Whisper large-v3 对原稿强制对齐，短语 5–15 个非标点字符。两步连续执行；命令与恢复办法见 [配音与验收](references/audio-quality.md)。
3. **语义导演表**：按完整语义合并相邻短语，每镜写理解目标、主体变化、最终结果和承接。端点与信息事件起点取真实短语边界，保留原文与毫秒。严格七列：`镜头｜时间｜配音文案｜画面类型｜画面设计｜动态变化｜画面衔接`，从 S001 编号。表后检查理解、重复、密度、真实性、强调、连续性，列素材缺口、视觉选择、高难镜头。
4. **画面与选效**：人物/场景用于经历与情绪；真实素材用于证据和操作；信息图用于关系和步骤；文字动效用于关键词与结论。按意图选主持人、主角、配角、第一人称视角，详见 [导演与风格](references/directing-style.md)。B-roll 先查本地模板，再按需查开源模板，最后最小适配。
5. **生图包与样片**：按 [生图包与分阶段审核](references/image-pack.md) 固定风格、角色参考和每镜输入输出，保存提示词与资产清单。场景、人物、道具按运动需要分开生；精确文字和界面用真实素材或排版。先完成少量代表静帧，审看后做短动效样片，确认问题镜头再扩全片。未获视觉认可的候选不能标为已定版；已明确授权的环节继续推进。
6. **HyperFrames 制作**：涉及 HTML、动效和渲染先读已安装 `hyperframes` 入口，再按需读 core、animation、registry、cli 等专项。绑定毫秒时间轴，动画可 seek、有限、确定；信息动画与字幕分层。本地字体和媒体稳定可用，不以示意图冒充实测界面。
7. **验证与交付**：运行本技能 `scripts/check_video_inputs.py`、`scripts/check_rendered_media.py` 和 HyperFrames `check --strict`，检查实际导出文件的规格、音轨、开头音频活动与全片解码；查看实际编码帧，尤其转场前中后、人物、字幕和最终结论。人工听验与结构校验分别记录，未复听不能写已逐字听验。输出视频、视觉表、无敏感值资产记录、验收说明，保留前版。

## 叙事与屏幕语言

开头第一帧展示实际效果，同时开始口播，不追加无声等待。A-roll 负责解释与承接，B-roll 展示结果、操作和验证；按语义推进，不按固定比例切换。每个关键步骤明确输入、动作和输出，附完整可复制的 Codex 提示词。详见 [留存与编排](references/retention-editing.md)。

参照用户的横屏讲解片：先让角色处在具体问题中，再切到信息画面解释原因与方法，随后回到操作或验证。人物镜头与信息镜头接力；让同一份材料、一个道具或一个问题贯穿，避免整片成为大标题加静态卡片。主持人、主角与第一人称按故事选用，不能为凑比例机械交替。

浅色手绘 A-roll 可放在宽幅场景框中，字幕放在下方独立区域。科普图解段可使用奶油点阵画布，主要信息在宽幅主体区展开，右上保留栏目水印。左下角 FUGui 陪伴头像属于历史可选模板；用户本次取消头像时不添加，也不为它压缩主体布局。按内容重排图解，给角色和字幕留出独立空间；人物情境与操作镜头仍按故事需要选用，不必全片套小头像。布局与克制的角色回应见 [导演与风格](references/directing-style.md)。需要更强视觉强调时可使用深蓝信息板。比较、缺失项、文件结构、验证回路各有不同骨架。长镜头要有对应旁白的信息变化，入场、背景呼吸、字幕跳动不能充数。

用户所说的“电视乱流”以实际参考为准。该参考的重点是深浅画面反差、人物情境与分阶段信息展开；不要默认添加雪花、RGB 色偏或扫描故障。局部错位是此前 v2 的试用方案，未获成片认可，不作为新版必备效果。需要时再按语义检索 registry 并适配。

## 输入检查工具

```bash
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/tudouni-ai-video"
python3 "$SKILL_DIR/scripts/check_video_inputs.py" "/项目/timeline.json" \
  --script "/项目/定稿.txt" --audio "/工程/audio/vo-full.wav" \
  --synthesis "/工程/audio/vo-synthesis.json" --align-text "/工程/audio/vo-align.txt"
```

`SKILL_DIR` 是实际技能目录；默认位于 `${CODEX_HOME:-$HOME/.codex}/skills/tudouni-ai-video`。工具核对原稿（保留标点、英文与数字，只忽略排版空白）、音频规格/哈希、一次合成记录、连续短语、镜头覆盖及事件边界。它不能代替声学对齐、真实复听或视觉检查。结构错误先修复，不能靠改状态字段宣称通过。

实际导出文件另运行：

```bash
python3 "$SKILL_DIR/scripts/check_rendered_media.py" "/项目/成片.mp4" \
  --report "/项目/encoded-media-qa.json" --max-onset-ms 250
```

此工具检查前 10 秒编码音频的活动起点和全片解码。活动不等于可懂口播，背景音乐也会触发；未人工复听继续保持 `listening_verified=false`。

首个案例、已验证范围与未完成事项见 [验证案例](references/validated-case.md)，需要复用工程或排查时读取。
