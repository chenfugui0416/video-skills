# 生图包与分阶段审核

本环节在定稿、全文配音与真实对齐之后。继续使用既有 FUGui、奶油蓝、音色、画幅与 HyperFrames，不因参考教程换角色或引擎。

## 文件与字段

在 iCloud 外工程内维护 `image-pack/`，发布包只保留最终视频、封面及必要的交付记录。

- `style.md`：角色原始身份参考、已选风格、色板、画幅、安全区、线条/材质、文字区域、禁止漂移项。区分参考、候选、用户认可版。
- `shots.json`：每镜 `shot_id`、真实 `start_ms/end_ms`、完整旁白、观众理解目标、画面类型、构图、承接、所需资产、提示词文件、运动目标、证据来源。与七列语义导演表按 S001 等编号对应；JSON 是执行索引，不另造一套分镜事实。
- `prompts/S001-*.txt`：具体角色动作、视角、景别、场景、道具、留白、画幅及相同风格约束；记录参考图与生成版本。保持人物身份，允许按叙事变视角。
- `assets.json`：`asset_id/shot_id/layer/file/sha256/source/reference/status`；layer 为 background、character、prop、real-evidence 或 typography。仅把可用文件标为 ready，缺图保持 missing，不用路径占位冒充完成。

## 分层与取舍

背景、人物和会独立运动的道具分别生成或提取；记录透明度、锚点、缩放与前后关系。静态且无需拆动的镜头可合并出图，说明理由即可，不强制每镜三张。透明素材检查边缘和背景残留。精确中文、数据和工具 UI 使用排版/真实截图，不能让生图模型伪造界面或结果。

## 扩片前检查

1. 从实际分镜选 2–3 个代表画面，至少覆盖角色情境与关键图解/操作，验证身份、风格、内容与字幕空间。
2. 将代表画面接入真实配音，做一个短动效样片，检查信息是否跟得上声音、人物视线、转场、字幕和重点呈现。按动作需要选时长，不固定为六镜或某个秒数。
3. 有明确问题时按镜头编号记录反馈：问题、证据、修改目标、可复用项、修改影响。角色漂移重做相关资产；时间错修镜头边界；只有画面变化复用有效配音；正文变动重做配音与对齐。
4. 已授权且满足当前视觉选择后扩全片，再补 BGM、信息动效和字幕的全片混音与验收。代码/技术通过和用户视觉认可分别记录，尚未审看不写“已认可”。

选效优先本地 registry，再查合适的开源模板，最后最小实现。局部高难镜头失败先修改该镜头，不让全片围绕失败方案返工。
